* let's shelf the sidebar pane for now. it's just not a priority now. I want to have the footer first. sidebar pane can be added later as a nice to have and we'll be more informed from the initial experience with the footer UI.
* I like the "spine" view idea. but I want to think more how to deal with deeper references. showing the full lineage as a tree is too verbose and takes too much space. so I want to explore some hybrid approaches:
   * first, we might want to fold single-descendant paths into breadcrumbs-chains. this is how most IDE file explorers do it: if the path is unambiguous, it is shown as `a/b/c/d` not a "ladder"-style tree. the tree-split happens when there is ambiguity. so multiple references can still be shown in the context of their outline structure, but the lineage is abbreviated so save vertical space. note that Logseq does something like this. we don't need to copy it, but it's a reference.
   * second, we need to do something about potentially long ancestor nodes (like multi-line paragraphs). I think we can truncate them with an ellipsis, and let user click or hover on it to see the full thing. these are just rough ideas. think of other alternatives and let's try them out.
