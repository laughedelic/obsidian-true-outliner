Lineage Rendering Sandbox

Both surfaces that quote an ancestor chain — the zoom breadcrumb trail and the backlinks footer's lineage rows — currently put the node's raw source into the DOM with appendText. Everything below is that same corpus under five policies. subdued is the one we are taking: live and separately clickable, with the colour accent dropped so the chain stays context, and no image embeds in a one-line row. Switch either surface to verbatim to see what ships today.

Backlinks footer

src/plugin/lineage-row.ts · footer-model.ts

Each chain is shown with the reference row it leads to. That row already renders inline markdown in full, which is what makes the verbatim lineage above it read as a defect rather than as a choice.

What this prototype is not. The inline parser here is a stand-in, written to make the policies comparable. The real implementation runs Obsidian's own MarkdownRenderer once and lets the policy decide what to keep from its output — which is also why plain is not a regex stripper: taking textContent from a real parse is the only way escapes, nested emphasis and bracket-bearing code spans come out right. The reference row under each footer chain stays fully live throughout, since that is what it already does and what a chain is being compared against.
