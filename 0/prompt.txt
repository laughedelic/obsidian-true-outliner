Context: this is the `obsidian-true-outliner` Obsidian plugin repo. Its e2e suite (`e2e/specs/*.e2e.ts`, run via WebdriverIO + `wdio-obsidian-service`) launches a real Obsidian Electron app per spec file. `scripts/run-e2e.mjs` is the normal entry point (`node scripts/run-e2e.mjs [desktop|mobile] [--group <name>]`) — it rebuilds the plugin, regenerates a generated hub fixture, snapshots/restores vault drift, then invokes `wdio run <config> --spec <file> --spec <file> ...` for every file in the named group (groups are decade-based prefixes on the two-digit spec filename, see `scripts/spec-groups.mjs`). A full group run of the `backlinks` group (10 files, prefixes 70-79) takes ~4 minutes and pops a real, focus-stealing Obsidian window for each spec file in sequence.

During a long review-fixing session today, the pattern that caused hours of pain: make a one-line fix, then re-run the WHOLE group to verify it and to run the negative control, because there was no fast documented way to run just the one changed test. Discovered mid-session (not documented anywhere): calling wdio directly bypasses the group wrapper's rebuild/hub-gen/drift-snapshot overhead and lets you target one file plus one test name:

```
node_modules/.bin/wdio run e2e/wdio.conf.mts --spec e2e/specs/77-footer-controls.e2e.ts --mochaOpts.grep "test name substring"
```

This took most single-test iterations from ~4 minutes to ~10-30 seconds. But it's an undocumented, manually-typed incantation, it still pops the Obsidian window, and when a FULL group run fails you still can't tell which test failed without scrolling raw stdout or re-running narrower — there's no structured "here's what failed" output.
